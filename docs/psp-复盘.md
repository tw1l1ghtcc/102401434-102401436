# PSP 复盘与总结

## 一、统计口径

本项目的 PSP 预估和实际耗时统一以 [PSP预估与实际耗时](psp.md) 为准，覆盖项目计划、设计、开发、检查、测试和文档整理等阶段。

本复盘不另行统计个人部分耗时，也不采用“等效手写工时”替代实际耗时。各阶段的具体数字见 psp.md。

| 项目 | 耗时 |
|---|---:|
| 预估总耗时 | 900 分钟（15 小时） |
| 实际总耗时 | 700 分钟（11 小时 40 分钟） |
| 实际比预估减少 | 200 分钟（3 小时 20 分钟） |

## 二、预估与实际差异

实际耗时低于预估，主要原因是第一次结对作业已经完成需求分析和交互原型，本次能够依据已有原型实现核心功能，减少重新设计页面和操作流程的时间。

两名成员按模块分工，通过 Git 分支、Fork 和 Pull Request 合并代码，减少重复开发。

## 三、开发中的额外工作

开发过程中还需要处理以下问题：

- 旧版本地数据缺少新版字段，需要兼容处理。
- 本地存储失败时，需要停止发布成功流程或恢复修改前的状态。
- 单元测试需要直接读取正式项目源码，并修正测试路径。
- 合并 README 时，需要保留成员信息、原型链接和原有说明。

这些工作属于现有 PSP 开发、检查、测试及文档整理阶段，不在本复盘中另加一套耗时数字。

## 四、收获与改进

1. 在开发前明确数据字段和模块接口，减少合并后的兼容性调整。
2. 明确文件分工，降低两人同时修改同一文件造成的冲突。
3. 每次提交 Pull Request 前运行相关测试，及时发现回归问题。
4. 使用 Google Chrome 检查实际操作流程，自动化测试与浏览器验收相互补充。
5. 后续按阶段及时记录实际投入时间，并保持 PSP 表格、复盘和博客的统计口径一致。
